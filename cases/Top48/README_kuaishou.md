# 快手动态性能用例

来源：`动态性能模型测试用例7.xlsx`，Sheet1 第 947～969 行。

- `PerformanceDynamic_kuaishou_0010`：7 步，精选视频切换并播放 10 秒 × 3、评论上滑/下滑各 2 次、点赞、收藏、返回桌面。
- `PerformanceDynamic_kuaishou_0020`：16 步，搜索“华为手机”、结果上滑/下滑各 3 次、直播榜第一名和下一直播各观看 15 秒、侧边栏快手小店、推荐上滑/下滑各 3 次、首件商品加购、返回桌面。

页面操作在 `kuaishou_common.py`；沿用 `DynamicAppCase` 的逐步 Perfetto 采集、等待、异常处理和日志清理。无需改动 main.py 中已有的用例入口。

定位参考设备 cff0cbff、快手 14.8.40.50567。weditor 的连接和 hierarchy 接口返回 HTTP 500，改用 uiautomator2 hierarchy 与 adb 主屏截图核对。设备有多个显示屏，uiautomator2 默认截图可能来自副屏；调试时需要核对主屏截图。控件仅使用 display-id=0 的节点；点击由实时节点边界计算，滑动由当前窗口尺寸按比例计算，通过 `input -d 0` 注入。

“加入购物袋”在当前版本对应商品详情的加购图标和规格面板的“加入购物车”。加购图标没有 id 或文本，按底栏节点边界关系定位；确认加入后验证购物车角标增加。当前支持“包装规格”下带价格的可用规格行，优先选择第二个规格；当前规格未成功加购且规格面板仍打开时依次尝试其他可见规格，兼容已达到限购数量的情况。若首件商品无可确认的加购入口或需要其他规格选择，会明确记录 WARNING 跳过并返回，不点击购买按钮。可见规格均无法加入时也会明确记录跳过。其他页面转换失败会抛出异常。

点赞/收藏通过 content-desc 确认状态；已点赞/已收藏时保留已有状态。搜索不发送私信，评论仅浏览。运行加购会增加测试账号购物车中的商品。

关闭侧边栏后，快手控件树仍可能保留可见的旧节点。通过抽屉实际展开宽度校验状态，防止点击移出屏幕的旧小店入口。

验证（2026-10-15）：0010 的 7 步连续真机通过；0020 的 1～9 步连续通过，修复抽屉旧节点后 10～13 步通过，修复规格加载等待和限购重选后 14～16 步通过。加购验证中第二个规格达到限购后改选“3层300张X3包”，购物车角标从 3 增至 4。验证日志在 `Result/kuaishou_validation_20261015/`。本次为实际页面操作及停留时间验证，未运行 Perfetto trace 采集/导出；代码继续复用工程既有采集框架。Python 编译检查、IDE 构建检查和 diff 空白检查通过（IDE 仅提供有限构建诊断）。
