# 百度与百度地图动态性能用例

步骤来源：根目录 `动态性能模型测试用例7.xlsx` → `新-7.0.2模型测试步骤`。

| 用例 | 步骤数 | 场景 |
| --- | ---: | --- |
| PerformanceDynamic_baidu_0010 | 11 | 文心问答、西安百度百科搜索与详情浏览 |
| PerformanceDynamic_baidumap_0010 | 8 | 钟楼搜索、西安钟楼驾车路线、启动及退出导航 |

现有空模板已重写，分别使用 `com.baidu.searchbox` 和 `com.baidu.BaiduMap`。
公共等待、比例手势和逐步采集在 `baidu_common.py`。未修改支付宝实现或当前负载运行列表。

## 运行

`main.py` 已有两个用例的导入。需要运行时，将现有 `case_list` 设置为：

```python
case_list = [PerformanceDynamic_baidu_0010, PerformanceDynamic_baidumap_0010]
```

保持手机已解锁、网络可用，提前完成应用首次协议及文心登录/介绍提示。
当前主入口注释了 `set_up`；两个用例在首次 `run_case` 时会自动完成环境准备。
百度地图仅申请前台粗略及精确定位权限，本次测试机已开启。文本问答和驾车导航不申请相机或麦克风权限。
启动和清理均保留其他应用后台，不清应用数据。

## 定位与页面校验

- 优先使用 resource-id、文字和 content-desc；地图导航操作均采用实际控件定位。
- 百度 15.78.0.10 底部中间的“文心一言”入口当前显示为“文心助手”无文字图标，使用屏幕比例。
- 文心问答明确切换普通“快速”模式，输入 `西安三天旅行攻略`。发送箭头从输入框父容器实时读取 bounds，排除清空图标，不依赖输入法高度。
- 百科首条结果当前为“百度AI·百度百科解答”卡片；优先用标题控件，无可用控件时点击经截图核实的百科标识比例位置，并确认进入百科小程序详情。
- 地图先按表格搜索 `钟楼`。当前定位上海，本地结果不包含目标时，在选择步骤补充 `西安钟楼` 查询；校验详情地址为陕西省西安市、路线终点为西安钟楼后才允许导航。
- 地图同名搜索栏和卡片通过 XML 的 resource-id 与屏幕内 bounds 区分。UiSelector 空 resourceId 会被忽略，因此不以其过滤搜索栏。
- Android 17 上本机的 adbutils `app_current()` 曾误报后台百科小程序；公共方法优先解析系统当前焦点，必要时读取 topResumedActivity。
- 点击使用控件中心或 `window_size()` 换算比例，不写死绝对像素；采用200毫秒单次点按兼容此机的点击响应，并按目标页面状态有限重试。
- 上下浏览各5次，方向相反；回桌面使用底部上滑手势。字体、键盘、布局或版本变化时仍需核实 Canvas 比例。

实测设备：`cff0cbff`，Android 17，1208×2624 竖屏；百度15.78.0.10、百度地图22.0.0。
weditor `http://192.168.1.161:17310/` 连接报 `Unsupported deviceId: Android:cff0cbff`，本次使用同机 uiautomator2 层级和截图核实定位。
