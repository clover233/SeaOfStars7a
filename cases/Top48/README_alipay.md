# 支付宝动态性能用例

步骤来源：工程根目录 `动态性能模型测试用例7.xlsx` 的 `新-7.0.2模型测试步骤`。

| 用例 | 步骤数 | 场景 |
| --- | ---: | --- |
| PerformanceDynamic_alipay_0010 | 19 | 出行、卡包、我的、转账页面、扫码相册预览 |
| PerformanceDynamic_alipay_0020 | 34 | 理财、测试聊天、会员、账单、余额、设置 |
| PerformanceDynamic_alipay_0030 | 10 | 搜索闪送、小程序首页/订单/我的 |
| PerformanceDynamic_alipay_0070 | 15 | 医疗健康、蚂蚁森林、淘宝闪购 |

`main.py` 已导入四个类。把需要运行的类加入现有 `case_list` 即可；本次未改变当前的负载用例运行列表。
当前主入口注释了 `set_up`，这四个用例的 `run_case` 会在首次执行时自动完成前置准备。

## 预置

- 支付宝已登录；手机网络可用。
- 0010 相册至少有一张测试图片。
- 0030 首次进入闪送时，需人工确认用户协议/隐私政策。本次测试手机已按用户确认完成该前置条件。订单和我的页面如要求登录，也需提前完成。
- 0020 默认使用本次用户确认的联系人“测试账号”和当前相册前5张照片。需预置该联系人、聊天记录和测试图片；可通过运行配置的环境变量覆盖：

```text
ALIPAY_TEST_CONTACT=测试账号
ALIPAY_TEST_PHOTOS=1,2,3,4,5
```

照片序号按照片出现顺序计数，跳过“拍照”格子和视频，必须为五个不同正整数。
本次相册前8项为视频，默认发送的前5张照片对应媒体编号9–13。
该用例将向指定联系人发送“动态性能测试”和所选五张图片。
消息列表主体为 Canvas，因此通过通讯录中完全匹配的好友 id 进入资料页，再点击“发消息”。
发送前同时校验原生聊天 Activity 和标题，避免把全局搜索建议误判成聊天；未找到或不唯一会中断。

`set_up` 使用当前 `SeaOfStarsAW.ut_device`，仅授权本用例需要的定位、相机或图片读取权限。
Android 13 以下使用 `READ_EXTERNAL_STORAGE`，Android 13 及以上使用 `READ_MEDIA_IMAGES`。
登录和协议提示会中断用例，避免把前置条件页面当成目标页面采集。

## 定位及采集

公共操作在 `alipay_common.py`，0020 专用操作在 `alipay_messages.py`。
优先使用 resource-id、文字和 content-desc。首页服务和消息同名时限定服务控件的 id。
无法获取控件的 Canvas 页面使用 `window_size()` 按比例换算；照片勾选使用控件 bounds 中心。
闪送返回支付宝首页使用屏幕左边缘侧滑，返回桌面使用底边上滑，均按屏幕尺寸换算。
上下滑使用相反的 y 方向，滑动次数和步骤编号与 Excel 一致。

比例位置于 2026-10-12 在支付宝 12.12.30、1208×2624 竖屏实机上核实。
分辨率变化会自动换算；字体缩放、布局和应用版本变化仍需核实位置。
当前稳健理财页的热销区为“大家都在买 / 一周热门榜”，第一款产品从榜单容器动态读取。

每个步骤单独调用现有 `start_perfetto_trace` 和 `stop_and_get_perfetto_trace`，保留 trace 与截图命名规则。
步骤失败时仍尝试导出该步骤 trace/截图，并保留原始异常；不会继续执行后续步骤。
Excel 新步骤表没有注明停留时长：0010 保留旧版适用步骤的 1/2 秒停留，其余页面默认 2 秒、每次滑动后 2 秒。
加载和定位等待按页面状态额外执行。清理只关闭用例日志处理器，保留应用后台。
