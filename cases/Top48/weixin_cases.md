# 微信动态性能用例 0010—0080

按《动态性能模型测试用例7.xlsx》第一张表 1633—1747 行编写，步骤顺序与数量保持一致。
`main.py` 已导入这些类，本次不修改运行队列。

- `0010`：图片群、视频浏览/转发、语音群。
- `0020`：添加朋友查询、朋友圈、拍摄入口、九张图片多选。
- `0030`：通讯录、头像、好友相册、推荐入口、扫码选图。
- `0040`：文字、语音、标准表情、视频/语音通话。
- `0050`：华为与 HarmonyOS 公众号、文章、官网菜单。
- `0060`：朋友圈拍摄入口、三张图片预览、位置选择、放弃草稿。
- `0070`：最近小程序中的瑞幸咖啡、人气 Top、商品与购物车。
- `0080`：拍照和录像发送。

## 定位和环境

优先从 uiautomator2 控件树读取文字、描述和边界。实机微信 8.0.79 的正文可能只导出一个
不可见根节点；macOS 自动使用随附 `weixin_ocr.swift` 的本地 Vision OCR，以识别框中心定位。
首次编译发生在 `set_up`，不会计入性能步骤。其他系统若控件树可用，无须 OCR；否则配置
`WEIXIN_OCR_COMMAND`，该命令接收截图文件路径，返回 JSON 数组：

```json
[{"text":"菜单","x":0.2,"y":0.9,"w":0.1,"h":0.03}]
```

所有框均为相对截图的 0—1 比例。纯图标与相册网格使用已经实机截图核对的比例布局；
网格行高按屏幕宽度计算。所有手势按运行时分辨率换算。

`0020/0030/0060` 在采集前生成九张纯色 PNG，放入专用相册“微信性能素材”，不会清理其他相册。
微信必须已登录；联系人和测试群需事先存在。好友查询默认使用官方标识 `weixin`，可通过
`WEIXIN_FRIEND_QUERY` 改为专用测试账号的微信号，不提交添加申请。

## 实发范围和适配

用户最新要求改为仅对置顶会话“测试”实发和拨号。代码从微信首页精确选中该会话，并在发送前
核对聊天标题或转发确认框；不从通讯录的同名联系人中猜选。`ALLOW_SEND = False` 可关闭实发。
`0030` 的好友资料浏览和 `0010` 的历史素材发送者仍可使用原有测试素材账号，不向它发送消息。
朋友圈浏览也按用户要求切换到“测试账号”的个人朋友圈；发布草稿场景仍从发现页的朋友圈入口进入。
朋友圈公开评论没有获得授权，单独记录为 `SKIP`。推荐名片验证到选择聊天页，不执行发送。
朋友圈图片草稿最终丢弃；瑞幸只加购物车，不下单。
通话出现“当前聊天存在风险，无法进行通话”等提示时，按用户要求点击“我知道了”，
记录原因并继续下一步；不会重拨以绕过该提示。

当前微信拍照和录像共用快门；录像使用按住/释放快门，替代表中的独立录像按钮。
没有对应公众号菜单、有效媒体或可见功能时，记录具体跳过原因，后续相关步骤一起跳过。

每个正式步骤仍调用项目的 Perfetto 开始/结束接口，并保存截图。结果目录中的
`step_results.json` 分别记录 `PASS`、`ADAPTED`、`SKIP`、`FAIL`、定位方式和 trace 导出状态。
OCR 与页面校验会增加步骤时间，分析性能时应结合 trace 中的实际交互区间。
