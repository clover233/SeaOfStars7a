# 美团动态性能用例

对应 `动态性能模型测试用例7.xlsx` 第1041～1093行，分别为0010的17步、0080的10步、0090原26步中删除13～18步后的20步。入口仍由main.py原有导入加载，公共实现位于meituan_common.py。

定位依据：2026-10-15，小米M154FF，Android 17，美团12.67.203。weditor连接报Unsupported deviceId，继续尝试Dump Hierarchy；最终使用uiautomator2控件树与截图核对。点击通过实时控件bounds换算中心，手势按window_size比例计算，主屏input -d 0注入；未写死屏幕像素。预订提示气泡关闭叉无语义节点，按气泡边界比例计算。

适配与替代：
- 首页“美食”替代“美食团购”，进入包含“美食餐厅”的餐厅列表。
- 0010优先进入当前可见第一份可加购食品；当前商家默认展示“刚刚搜过”，替代表中的“推荐”分类。
- 第二次食品加购在购物车面板点击有描述的“增加”，验证数量达到2份，随后清空；不触发结算或支付。
- 按用户最新要求，0090原第13～18步（输入24小时药店、搜索、进店、加购、清空购物车）已删除。点击搜索框后直接执行原第19步返回外卖界面，运行结果按剩余20步连续编号。
- 0090外卖“我的”实测只显示账号与设置，无“我的地址”入口；21～24步记录SKIP。其他版本出现入口时可进入列表/新增表单；地址编辑定位尚未核验，22、23步仍记录SKIP，避免猜测控件和提交错误地址。新增表单仅浏览，不填写虚构地址。

每步保留Perfetto与截图采集；trace名称包含PASS/SKIP/FAIL。结果目录中的step_results.json记录每一步状态和跳过/失败原因。只对明确的功能缺失或服务不可用跳过，页面导航和定位失败仍抛异常。set_up检查美团安装与解锁，不清后台。

验证：使用独立临时脚本串跑真实UI操作与逐步截图（暂时替换trace启停函数，不修改工程采集接口）；因此UI验证结果不代表已完成正式Perfetto性能采集。截图和UI结果保存在/tmp/meituan_probe/results。Python编译检查通过；IDE构建接口返回成功，但提示Python构建诊断受限。

实机UI验证结果：0010为17 PASS，0080为10 PASS；删除药店步骤后的0090为16 PASS、4 SKIP、0 FAIL（地址相关四步）。0090最终冒烟验证将滑动间停留缩短为0.2秒，工程实现仍使用正式停留时间。首页入口已增加吸顶搜索栏遮挡检查，返回首页时先恢复频道可点击位置。
